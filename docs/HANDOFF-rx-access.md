# Доступ к сервису классификации — для разработчика Directum RX

Обновлено 2026-08-26. Документ описывает, как обратиться к сервису и что для этого нужно.

## Адрес

```
http://192.168.189.140:8010
```

Машина слушает `0.0.0.0:8010`, то есть доступна из локальной сети. Адрес актуален,
пока сервис поднят на этой машине; при переносе меняется (см. `docs/DEPLOY.md`).

Проверка доступности:

```bash
curl http://192.168.189.140:8010/health
# {"status":"ok","agent_ready":true,"classifier_entries":2108}
```

`agent_ready: false` — модель ещё загружается, запросы отправлять рано.

## Аутентификация не требуется

**Логин и пароль не нужны.** Эндпоинты сервиса открыты: ни `/classify`,
ни `/integration/classify-document`, ни страницы бэк-офиса не требуют учётных данных.

Переменные `BACKOFFICE_USER` / `BACKOFFICE_PASSWORD` в `.env` на поведение не влияют:
функция проверки Basic Auth в коде объявлена, но ни к одному маршруту не подключена.
Отдельно об этом — в разделе «Замечание по безопасности».

## Учётные данные RX больше не нужны сервису

Раньше сервис сам забирал тело документа из RX по OData и для этого требовал
учётную запись RX. **Теперь RX передаёт текст обращения в запросе**, поэтому
никакие креды RX сервису передавать не нужно.

Исключение — если вы вызываете старым способом, только с `document_id`: тогда
сервис по-прежнему ходит в RX по OData и ему нужны `RX_ODATA_URL`, `RX_USER`,
`RX_PASSWORD` в его `.env`. На основном пути это не требуется.

## Вызов

```
POST http://192.168.189.140:8010/integration/classify-document
Content-Type: application/json
```

```json
{
  "document_id": 26,
  "appeal_text": "Текст обращения гражданина"
}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `appeal_text` | да | текст обращения |
| `document_id` | нет | возвращается в ответе как есть, для связи с карточкой RX |

Ответ:

```json
{
  "document_id": 26,
  "applicant_fio": "Иванов И.И.",
  "applicant_email": "ivanov.i.i@yandex.ru",
  "summary": "Краткая суть обращения.",
  "reasoning": "Обоснование модели по всем вопросам, не более 1000 символов.",
  "questions": [
    { "code": "0005.0005.0056.1160", "question": "Обращение с твердыми коммунальными отходами" }
  ]
}
```

Проверка одной командой:

```bash
curl -X POST http://192.168.189.140:8010/integration/classify-document \
  -H "Content-Type: application/json" \
  -d '{"document_id": 26, "appeal_text": "Не вывозят мусор две недели"}'
```

Полный контракт, коды ошибок и особенности (несколько вопросов, коды из 5 сегментов,
процедурные коды) — в [INTEGRATION.md](INTEGRATION.md). Живые схемы — Swagger на
`http://192.168.189.140:8010/docs`.

## Замечание по безопасности

Сервис открыт: любой, кто видит порт 8010, может отправлять обращения на классификацию
и читать статистику бэк-офиса, включая тексты ранее обработанных обращений
(персональные данные по 59-ФЗ).

Пока сервис работает в закрытом контуре стенда, это приемлемо. Перед продуктивным
использованием нужно закрыть доступ — по-хорошему одним из двух способов:

* подключить уже объявленную в коде проверку Basic Auth к маршрутам (правка небольшая), либо
* закрыть сервис на уровне сети: доступ к 8010 только с адреса сервера RX.

Учётные данные для такой защиты будут переданы отдельно и **не должны храниться в этом
документе или в репозитории**.
