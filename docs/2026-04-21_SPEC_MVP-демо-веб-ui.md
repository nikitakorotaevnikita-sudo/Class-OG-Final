## Цель

Минимальное живое демо для показа агента классификации обращений граждан целевому пользователю — **оператору Directum RX**.

Критерий успеха: оператор открывает браузер, вставляет текст обращения (или жмёт «Загрузить пример»), видит карточку результата и проходит весь рабочий цикл [Подтвердить / Исправить / Отклонить] — точно как делал бы в финальной интеграции с Directum RX.

## Бэкенд

### Изменения в `src/api_server.py`

**1. Расширить `ClassifyResponse` — добавить `log_id`**

Сейчас `ClassificationResult.log_id` есть, но в API-ответ не пробрасывается. Без него фронт не сможет верифицировать результат.

```python
class ClassifyResponse(BaseModel):
    appeal_id: Optional[str]
    log_id: Optional[str]          # ← добавить
    vid_obrascheniya: str
    ...
```

**2. Новый эндпоинт `POST /verify`**

```python
class VerifyRequest(BaseModel):
    log_id: str
    action: Literal["confirm", "correct", "reject"]
    operator_codes: Optional[list[str]] = None  # обязателен для action="correct"

@app.post("/verify")
async def verify(request: VerifyRequest):
    logger = get_logger()
    if request.action == "confirm":
        logger.confirm(request.log_id)
    elif request.action == "correct":
        if not request.operator_codes:
            raise HTTPException(400, "operator_codes обязательно для correct")
        logger.correct(request.log_id, operator_codes=request.operator_codes)
    elif request.action == "reject":
        logger.reject(request.log_id)
    return {"status": "ok", "log_id": request.log_id, "action": request.action}
```

**3. Новый эндпоинт `GET /examples`**

```python
@app.get("/examples")
async def get_examples():
    path = Path(__file__).parent.parent / "data" / "test_appeals.json"
    with open(path, encoding="utf-8") as f:
        return {"examples": json.load(f)}
```

**4. Отдача статики**

```python
from fastapi.staticfiles import StaticFiles
app.mount("/static", StaticFiles(directory="src/static"), name="static")

@app.get("/")
async def index():
    return FileResponse("src/static/index.html")
```

```
│   ▸ Показать JSON ответа                                 │
└──────────────────────────────────────────────────────────┘
```

### Поведение

| Действие | Реакция |
|---|---|
| Выбор пункта в dropdown «Примеры» | Текст пункта подставляется в textarea |
| [Классифицировать] | Дизейбл кнопки, спиннер, `POST /classify {appeal_text}` → рендер карточки |
| [✓ Подтвердить] | `POST /verify {log_id, action:"confirm"}` → toast «Подтверждено» → блок гасится |
| [✎ Исправить] | Раскрывается инлайн-форма «Введите код вопроса:» + поле + [Сохранить] → `POST /verify {log_id, action:"correct", operator_codes:["..."]}` → toast |
| [✗ Отклонить] | `POST /verify {log_id, action:"reject"}` → toast «Отклонено» → блок гасится |
| [▸ Показать JSON] | Раскрывается `<pre>` с полным JSON ответа `/classify` |

### Цветовая индикация уверенности

| Уверенность | Цвет полосы | Дополнительно |
|---|---|---|
| ≥ 80% | Зелёный | — |
| 65–79% | Жёлтый | — |
| < 65% | Красный | Плашка «⚠️ Требует верификации» |

### Multi-вопрос

Если в результате несколько вопросов — рисуем несколько карточек подряд. Кнопки [Подтвердить/Исправить/Отклонить] **одни на всё обращение** (как и в `appeals_logger`, который работает с `log_id` обращения целиком).
