# Развёртывание на новой машине

Чеклист переноса прототипа классификатора обращений. Что передать разработчику RX — в конце.

---

## 1. Требования к машине

| | |
|---|---|
| Docker | Docker Desktop (Windows/macOS) или Docker Engine (Linux) |
| Диск | **~10 ГБ** свободно: образ 8.8 ГБ (тянет CUDA-сборку torch) + слои |
| RAM | ~1.5 ГБ на контейнер. При Docker Desktop на WSL2 учитывать, что виртуальная машина забирает больше и не возвращает — см. «Известные грабли» |
| Сеть | доступ к Ario **из корпоративной сети или через VPN**, доступ к OData RX, открытый входящий порт для RX |
| Python на хосте | для установки в Docker **не нужен**; для установки без Docker — 3.11, 3.12 или 3.13 (см. шаг 5б) |

## 2. Что переезжает с репозиторием, а что нет

**Переедет с `git clone`** (проверено, всё в индексе):

* боевая векторная база `data/vector_db_adapted_v3/` — пересобирать не нужно;
* адаптеры и обученные компоненты `models/adapter_v1.*`, `models/ltr_v1.json`;
* файлы, которые монтируются в контейнер и должны существовать до старта: `data/appeals_log.jsonl`, `data/request_log.jsonl`, `data/historical_verified.jsonl`, `data/classifier_annotations.json`, `data/allowed_codes_top69.json`;
* данные классификатора `data/classifier_flat.json`, `data/classifier_hierarchy.json`.

**НЕ переедет — передать отдельно, безопасным каналом:**

* **`.env`** — он в `.gitignore`. Содержит ключ Ario и учётные данные RX.
* **Кэш моделей Hugging Face** — опционально, см. шаг 4.

> Файлы из списка выше монтируются как bind-mount **файлов**, а не папок. Если какого-то из них не будет на диске, Docker создаст на его месте **каталог**, и сервис упадёт при записи лога. После `git clone` они на месте — специально ничего создавать не нужно.

## 3. Заполнить `.env`

Взять `.env.example` за основу. Обязательный минимум:

```bash
# LLM
LLM_PROVIDER=ario
ARIO_API_KEY=<ключ>
ARIO_BASE_URL=https://gpt.ario.directum360.ru/v1
ARIO_MODEL=Qwen/Qwen3.6-35B-A3B

# Доступ к Directum RX — НЕОБЯЗАТЕЛЕН.
# RX присылает текст обращения в запросе, поэтому на основном пути OData не нужен.
# Заполнять только если RX будет вызывать по document_id, без текста.
# RX_ODATA_URL=http://<адрес-стенда-RX>/integration/odata
# RX_USER=<логин>
# RX_PASSWORD=<пароль>

# Активная векторная база и параметры поиска
VECTOR_DB_DIR=data/vector_db_adapted_v3
TOP_K_CANDIDATES=50
MIN_CONFIDENCE=0.65
ENABLE_HEURISTIC_RERANKER=false

# Фоллбэк и процедурные детекции (боевые значения)
ENABLE_FULL_CLASSIFIER_FALLBACK=true
FULL_FALLBACK_SIM_THRESHOLD=0.15
ENABLE_REPEAT_DETECTION=true
ENABLE_WITHDRAWAL_DETECTION=true

# Машинно-зависимое
HF_CACHE_DIR=<путь к кэшу HF на этой машине>
HOST_PORT=8010
```

**`FULL_FALLBACK_SIM_THRESHOLD` не менять произвольно.** Значение 0.15 подобрано под базу `vector_db_adapted_v3`: у неё similarity топ-1 лежит в районе 0.15–0.35. При завышенном пороге фоллбэк срабатывает на каждом обращении и съедает бюджет LLM.

## 4. Кэш моделей Hugging Face

Контейнеру нужна модель эмбеддингов `intfloat/multilingual-e5-base` (~435 МБ). Два пути:

**А. Скопировать кэш с прежней машины** — быстрее и работает без интернета:

```
старая машина:  C:\Users\<пользователь>\.cache\huggingface
новая машина:   любой путь → прописать его в HF_CACHE_DIR
```

**Б. Дать контейнеру интернет** — оставить `HF_CACHE_DIR` пустым. Docker смонтирует пустой каталог `./.hf-cache`, и модель скачается при первом старте. Если доступа к Hugging Face нет, сервис не поднимется: `/health` будет отдавать `agent_ready: false`.

## 5. Запуск

```bash
docker compose build classifier
docker compose up -d classifier
curl http://localhost:8010/health
# {"status":"ok","agent_ready":true,"classifier_entries":2108}
```

Первый старт — до минуты: загружается модель эмбеддингов. `agent_ready: false` означает «ещё грузится».

Смоук-проверка классификации:

```bash
curl -X POST http://localhost:8010/classify \
  -H "Content-Type: application/json" \
  -d '{"appeal_text": "Не вывозят мусор две недели, контейнеры переполнены"}'
```

Ожидаемо: код из раздела ЖКХ (`0005.0005.0056.*`), `agent_ready` уже `true`, `llm_model` — `Qwen/Qwen3.6-35B-A3B`.

Проверка сценария RX — именно так его вызывает RX, текст приходит в запросе:

```bash
curl -X POST http://localhost:8010/integration/classify-document \
  -H "Content-Type: application/json" \
  -d '{"document_id": 26, "appeal_text": "Не вывозят мусор две недели"}'
```

Ожидаемо: `document_id: 26`, код из раздела ЖКХ, непустой `reasoning`.

Устаревший путь — вызов **без текста**, только с `document_id`: тогда сервис сам идёт в RX по
OData. Ответ `502` на таком вызове означает, что тело документа не достали — проверять
`RX_ODATA_URL`, учётные данные и доступность стенда, а не классификатор. На основном пути
(с `appeal_text`) этой зависимости нет.

## 5б. Установка без Docker

Для машины, где Docker не нужен или недоступен (в том числе офлайн-стенда), в корне лежат
установщики. Они создают venv, ставят зависимости и заполняют `.env` в диалоге:

```
install.bat           # обычная установка, зависимости с PyPI
install_offline.bat   # без интернета: колёса и модель из offline_bundle/
launch.bat            # запуск сервиса
```

Принимается Python 3.11, 3.12 или 3.13. Пароль RX установщик **не подставляет**: если нажать
Enter, поле останется пустым и будет предупреждение — вызов по `document_id` вернёт 502.
Это сделано намеренно, чтобы сервис не работал под чужой учётной записью.

Подробности офлайн-варианта — в комплекте переноса: `offline_bundle/` с колёсами и локальной
моделью эмбеддингов, плюс скрипты `check_env.py` и `set_env_keys.py` для диагностики `.env`.

## 5в. Настройки через бэк-офис

Модель LLM и параметры доступа к RX правятся из интерфейса — вкладка настроек в бэк-офисе,
без ручной правки `.env`:

```
GET  /api/settings           # текущие значения; секреты отдаются замаскированными
POST /api/settings           # сохранить
POST /api/settings/test-rx   # проверить связь с RX
```

Изменения пишутся в `.env`, поэтому **вступают в силу после перезапуска сервиса** —
конфигурация читается один раз при старте.

> **Внимание.** Эти эндпоинты сейчас **не требуют аутентификации**: функция проверки Basic Auth
> в коде объявлена, но ни к одному маршруту не подключена. То есть любой, кто видит порт
> сервиса, может прочитать настройки и подменить креды RX и модель LLM. Перед продуктивным
> использованием доступ нужно закрыть — подключением проверки к маршрутам либо сетевым
> ограничением на порт.

## 6. Сеть — проверить в обе стороны

Самая частая причина «ничего не работает»:

| Направление | Зачем | Признак проблемы |
|---|---|---|
| контейнер → OData RX | **только для вызова по `document_id`**; на основном пути не нужен | `502` на `/integration/classify-document` |
| контейнер → Ario | классификация | `500`, в логах контейнера таймаут/недоступность LLM |
| контейнер → Hugging Face | только при пустом кэше моделей | `agent_ready: false` не проходит |
| RX → порт 8010 новой машины | вызовы от RX | RX не может подключиться; проверить firewall |

Порт снаружи меняется через `HOST_PORT` в `.env` — правка `docker-compose.yml` для этого не нужна.

## 7. Что передать разработчику RX

1. **Новый базовый URL** — `http://<хост>:8010`.
2. **[HANDOFF-rx-access.md](HANDOFF-rx-access.md)** — короткая памятка: адрес, вызов и то, что
   учётные данные для обращения к сервису не нужны.
3. **[INTEGRATION.md](INTEGRATION.md)** — контракт целиком.
   **Контракт изменился:** RX передаёт текст обращения в запросе (`appeal_text`), `document_id`
   стал необязательным. Формат ответа прежний, вызов только с `document_id` продолжает работать.
3. **Ссылку на Swagger** — `http://<хост>:8010/docs`, живые схемы запросов и ответов.
4. Проговорить четыре момента, на которых обычно спотыкаются:
   * `reasoning` — **один блок на верхнем уровне** ответа, а не поле внутри каждого вопроса;
   * **вопросов может быть несколько**, первый — основной;
   * код может состоять из **5 сегментов**, а не 4 — валидация `XXXX.XXXX.XXXX.XXXX[.XXXX]`;
   * к тематическим кодам добавляются **процедурные**: `0001.0002.0027.0131` (просьба отозвать обращение) приходит **первым** элементом, `0001.0002.0027.0125` (повторное обращение) — дополнительным.
5. Договориться, что RX опрашивает **`GET /health`** перед отправкой документов и корректно обрабатывает `503` (агент ещё не готов).

## 8. Известные грабли

**Жёсткие пути в конфигурации.** Все машинно-зависимые значения вынесены в `.env` (`HF_CACHE_DIR`, `HOST_PORT`) — `docker-compose.yml` править не нужно. Если в нём снова появится абсолютный путь, при переносе он молча смонтирует пустой каталог.

**Docker Desktop на WSL2 не возвращает память Windows.** Виртуальная машина разрастается под пиковую нагрузку и держит память. Лечится файлом `%USERPROFILE%\.wslconfig`:

```ini
[wsl2]
memory=4GB
autoMemoryReclaim=gradual
swap=2GB
```

Применяется после `wsl --shutdown` — контейнеры при этом перезапустятся.

**Место на диске внутри виртуального диска Docker.** Windows может показывать мало свободного места на C:, тогда как внутри `docker_data.vhdx` его достаточно, и сборка образа проходит, почти не расходуя место на хосте. Прежде чем переносить хранилище Docker на другой диск, стоит проверить: `docker run --rm <образ> df -h /`.

**Обработка последовательная.** Запросы выполняются по одному, параллельной обработки нет — при потоковой загрузке это влияет на время. Подробнее: [EPIC_load-scaling.md](EPIC_load-scaling.md).

**Служба Docker может не подняться сама.** Если движок недоступен (`cannot connect to the Docker API`), а процессы Docker Desktop висят — проверить службу `com.docker.service`, она бывает остановлена:

```bash
powershell -Command "Start-Service com.docker.service"
```
