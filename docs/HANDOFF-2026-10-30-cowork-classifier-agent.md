## 3. Что сделано в этой сессии (кратко, по порядку)

**`main`**
- Таймаут ожидания LLM: был зашит 120 с у `ollama`, стал общей настройкой
  `LLM_TIMEOUT_SEC` (коммит `251310a`), затем 360 с по умолчанию (`e85ae00`).
  Таймаут **не повторяется** (повтор только при rate limit, APIError, битом JSON).
  Если в `.env` стенда явно `LLM_TIMEOUT_SEC=300`, действует оно.

**`qwen3-embedding`** — эксперименты по качеству поиска
- Обогащение запроса перед поиском (`src/query_enrichment.py`, `4106edc`): LLM
  пересказывает вопрос языком классификатора (суть, ключевые фразы, синонимы).
  Режим `replace` — искать только по пересказу. В результат классификации добавлены
  `fallback_trigger`, `query_enrichments`, `retrieval_candidates`.
- Скрипт `scripts/enrichment_eval.py` (`95e24bb`): прогон выборки в вариантах
  baseline/qe/append/replace, xlsx «Сводка» + «Детально».
- Сквозной замер на 72 обращениях (ii25_test 56 + ветераны 5 + выборка 11):

  | Связка | Top-1 | Правильный код в кандидатах | Фолбэк |
  |---|---|---|---|
  | e5 + адаптер (стенд) | 21 (29,2%) | 50 | 10 |
  | e5 + предобработка | 20 | 50 | 7 |
  | Qwen3 без предобработки | 21 | 49 | 6 |
  | **Qwen3 + предобработка replace** | **24 (33,3%)** | **55** | **1** |

  Эффект только у связки; Qwen3 два прогона совпали один в один. +3 из 72 — в
  пределах шума, снижение фолбэков — устойчиво по всем наборам. Мимо раздела (L2)
  почти без изменений (18 против 19). Сводка — `eval_results/e2e_summary_all.xlsx`
  (локально, см. §5).

**ArioCowork и интеграция RX** — разведка
- Agents API платформы, авторизация, поведение агентов (§4).
- Схема взаимодействия RX ↔ агент (в чате, не в документе): RX вызывает агента из
  асинхронного обработчика; агент ходит в RX только через MCP.
- Фича «поиск похожих документов» (документ оператора) — обсуждали, отложена.

**`research/quality-followups-68`** — спецификация агента-классификатора
- Редакции 1–3, ревью «сторонним исполнителем» (builder check), согласовано.

## 4. Факты о платформе и стенде (проверено)

**ArioCowork** (LibreChat)
- Адрес внутри сети: `cowork.directum360.ru` → `172.16.18.66`, отвечает напрямую,
  без прокси.
- Agents API: `POST https://cowork.directum360.ru/api/agents/v1/chat/completions`

  HTML-страницу с кодом 200.
- Авторизация: только `Authorization: Bearer <ключ>`; `Api-Key`, `X-API-Key`,
  `api-key`, ключ без префикса — 401.
- `model` = ID агента, обязателен: без него 400 `missing_model`, чужое имя — 404.
- Агенты (по `/models`): `agent_c8-QbnRyU57bnDSX8a2pk` «ОГВ» (Ario),
  `agent_R2WYqZSa1PbRuvJx_X5mX` «Правовой отдел», `agent_dHiGafayEQCIkWr-pUffJ`
  «УРОГ», `agent_RlgTZukMiNmPuz_0N3FtR` «Контролер».
- Ключ API оператор показал в чате — **в репозиторий не записан**; оператору
  рекомендовано перевыпустить. Если ключ нужен — просить вписать в `.env` самому.
- Функции из `tools` запроса агент **игнорирует**, вызывает только подключённые на
  платформе. `response_format: json_object` + инструкция → чистый JSON (проверено).
- Агент «ОГВ»: ~35K токенов базового контекста, ~70K с одним вызовом MCP; у него

  транспорт, API Key или OAuth.
- В RX (карточка «CoworkOGV», интерфейс OpenAI) у оператора не нашлось поля для ID
  агента — без него вызов не заработает; варианты (доработка RX или прослойка) не

**Стенд RX** — одна машина: `governmentgenai.directum360.ru` = `172.16.104.68`
- OData: `http://172.16.104.68/integration/odata`, Basic; учётка в `.env`.
- На этой же машине развёрнут наш классификатор (`main`, Docker).
- `$metadata`: обращения — `IRequests` (`IRequestDto` ← входящий документ);

## 6. Правила работы с оператором

- **Язык** — русский; технические документы можно по-английски.
- **Не читать тексты обращений граждан** без явного указания оператора (ПДн,
  59-ФЗ). Прогонять через пайплайн, отдавать результат файлом; в ответах — только
  id, коды, метрики. Агент «ОГВ» в ответах может цитировать вложения с ФИО — не
  повторять.
- **README в `main`** — обновлять только по явной просьбе.
- **После каждой фичи** сообщать, поднят ли сервис 8010 с этой правкой (PID, старт,
  `/health`) или нет.
- **`.env` не коммитить**; пароли и ключи не писать в документы; не вводить пароли
  за пользователя (`net use` и т. п.).
- **Push** — когда оператор просит; ветки называть так, как он назвал.
- Контейнер для проверки не собирать, если просят «локально».
- Принцип проекта: агент предлагает, человек утверждает; запись в RX — только через
  подтверждение.

## 7. Грабли

- **Исследовательская ветка отстаёт от `main` на 64 коммита.** Слияние `main`
  даёт конфликты в `README.md`, `docs/INTEGRATION.md`, `src/classifier_agent.py`,
  `src/integration_api.py`, `tests/test_dedupe_in_classify.py`,
  `tests/test_integration_text_input.py` и журналах. В ней есть три доработки,
  которых нет в `main`: `ENABLE_QUESTION_DEDUP`, `LLM_APPEAL_CHAR_LIMIT`,
  `FULL_FALLBACK_INCLUDE_PATH`. Слияние откатили; код писать в `int-og`.
- **Системный прокси** (`HTTP_PROXY=127.0.0.1:10809` на старой машине) ломает
  внутренние адреса (503 / WinError 10061). В коде — `src/proxy_policy.py`
  (`uses_env_proxy`, только на `main`), настройки `RX_VIA_PROXY` / `LLM_VIA_PROXY`.
  В Docker Desktop свой прозрачный прокси — RX из контейнера недоступен; на Linux
  Docker Engine проблемы нет.
- **Python** — `venv\Scripts\python` (системный Python без `groq` и др.). Тесты:
  `venv\Scripts\python -m pytest tests/` — 3 давних падения в
  `test_candidate_rerank` не связаны с правками.
- **Кириллица в heredoc** через Bash на Windows иногда ломается — правки русского
  текста делать через Edit/Write.
- **Фолбэк по порогу** `FULL_FALLBACK_SIM_THRESHOLD=0.15` калиброван под e5; у Qwen3
  не срабатывает ни разу, работает только сигнал LLM `candidates_insufficient`.
- На стенде фолбэк, по данным прошлых сессий, выключен (контекст прежней модели
  64K) — с моделью 256K это можно пересмотреть.
