# Установка на стенд без интернета

Проверено целиком 2026-08-26: чистая папка → комплект под Python 3.11 → установка
только из локальных колёс → сервис поднялся, `/health` вернул `agent_ready: true`.

---

## Коротко

На машине **с интернетом**, из корня проекта:

```bash
python scripts/make_offline_bundle.py --python-version 3.11
```

Скопировать проект на стенд (**без `venv`** — см. ниже) и там запустить:

```bash
install_offline.bat
```

Установщик сам проверит комплект, создаст окружение из колёс, заполнит `.env`,
положит готовую векторную базу и в конце прогонит проверку. Проверить отдельно:

```bash
python scripts/check_offline.py --stage pre
```

## Что было не так раньше

Три причины, по которым установка не заводилась. Все три теперь либо исправлены в
коде, либо ловятся проверкой до начала установки.

### 1. Флаг офлайна не доходил до библиотеки

`huggingface_hub` фиксирует `HF_HUB_OFFLINE` **один раз — в момент своего импорта**.
Модули проекта импортировали `sentence_transformers` раньше, чем `config` (а `.env`
читает именно `config`). То есть строка `HF_HUB_OFFLINE=1` в `.env` не действовала:
библиотека уже была загружена в онлайн-режиме и шла в сеть за метаданными модели —
`FileMetadataError`, притом что файлы модели лежали рядом.

Исправлено модулем [`src/env_bootstrap.py`](../src/env_bootstrap.py): он читает `.env`
и импортируется первым — раньше `torch`, `transformers` и `sentence_transformers`.
Онлайн-поведение не изменилось (зеркало HF по-прежнему подставляется).

Проверить руками:

```bash
python -c "import sys; sys.path.insert(0,'src'); import env_bootstrap, huggingface_hub.constants as c; print(c.HF_HUB_OFFLINE)"
```

### 2. Колёса были собраны под другой Python

Колёса скомпилированных пакетов привязаны к ABI интерпретатора: `torch-2.13.0-cp313-…`
ставится **только** на Python 3.13. Комплект был собран под 3.13, а на стенде стоял
3.11 — `pip install --no-index` обязан был упасть, и падал.

Теперь это ловит `check_offline.py --stage pre` ещё до создания окружения и говорит,
каких колёс не хватает. Собирать комплект нужно под тот минор, который стоит **на
стенде**, а не на машине сборки:

```bash
python scripts/make_offline_bundle.py --python-version 3.11   # или 3.12 / 3.13
```

### 3. Скопированный `venv`

`venv` не переносится между машинами: лаунчеры в `Scripts\` содержат абсолютный путь
к создавшему их интерпретатору. Результат — `Fatal error in launcher: Unable to create
process using …`.

`install_offline.bat` теперь проверяет окружение (`venv\Scripts\python.exe -m pip
--version`) и пересоздаёт его, если оно нерабочее. Все вызовы идут через
`python -m pip`, а не через `pip.exe`. **При переносе `venv` копировать не нужно.**

## Из чего состоит комплект

`offline_bundle/`, около 1.3 ГБ:

| Что | Размер | Зачем |
|---|---:|---|
| `wheels/` | ~250 МБ | все зависимости под целевой ABI, 78 колёс |
| `models/multilingual-e5-base/` | ~1.1 ГБ | модель обычными файлами, не кешем HF |
| `vector_db_prebuilt/` | ~9 МБ | готовые векторы: стенду не нужно считать 2108 записей |
| `env.stand.example` | — | шаблон `.env` с офлайн-флагами |

Модель кладётся **каталогом файлов**, а не кешем `~/.cache/huggingface`: кеш требует
точной структуры `snapshots/<sha>/` с симлинками, и на Windows без прав на симлинки
он ломается.

## LLM на изолированном стенде

Retrieval работает локально, но второй этап — это LLM. `groq`, `gemini` и `ario`
требуют интернета, поэтому на закрытом стенде подходят только:

* **`custom`** — любой OpenAI-совместимый endpoint внутри сети (vLLM, LM Studio,
  gpt-oss). Задать `CUSTOM_LLM_BASE_URL`, `CUSTOM_LLM_MODEL`, при необходимости
  `CUSTOM_LLM_API_KEY`. Связь проверяется кнопкой в бэкофисе (`/backoffice`,
  раздел «Настройки») или запросом `POST /api/settings/test-llm`;
* **`ollama`** — модель на самом стенде, `OLLAMA_BASE_URL=http://localhost:11434`.

Ключи и адреса меняются из бэкофиса без перезапуска сервиса: `apply_runtime()`
раскладывает настройки и в `os.environ`, и в уже импортированные модули.

## Ход установки

```
install_offline.bat
  [1/6] поиск Python 3.11 / 3.12 / 3.13
  [2/6] check_offline.py --stage pre   колёса под этот ABI? модель? база?
  [3/6] venv (нерабочий — пересоздаётся)
  [4/6] pip install --no-index --find-links=offline_bundle\wheels
  [5/6] .env: офлайн-флаги, локальная модель, провайдер LLM, креды RX
  [6/6] готовая база → data\<VECTOR_DB_DIR>, затем check_offline.py --stage post
```

Запуск сервиса после установки:

```bash
venv\Scripts\python.exe -m uvicorn src.api_server:app --host 0.0.0.0 --port 8010
```

## Проверка

`scripts/check_offline.py` работает в две стадии.

**`--stage pre`** — любым найденным интерпретатором, только stdlib, до установки:
версия и разрядность Python, совпадение тегов колёс с ABI, полнота каталога модели,
наличие готовой базы, типовые проблемы `.env` (файл `.env.txt` от «Блокнота», UTF-16
от `Out-File` без `-Encoding utf8`, BOM, отсутствие активных строк
`HF_HUB_OFFLINE` / `EMBEDDING_MODEL`).

**`--stage post`** — интерпретатором `venv`, после установки: импорты, загрузка
модели без сети, согласованность базы с моделью по размерности, реальный поиск.

Прогон в стадии `post` идёт **отдельным процессом**: порядок импортов и есть предмет
проверки, а в процессе самого скрипта HF-библиотеки уже подтянуты — результат был бы
ложноотрицательным.

Что должно получиться на исправном стенде:

```
  [OK  ] Python 3.11.9 (cp311)
  [OK  ] HF_HUB_OFFLINE=1 — сеть в HF-библиотеках запрещена
  [OK  ] офлайн-режим HF активен (флаг дошёл до huggingface_hub)
  [OK  ] модель загружена без сети, dim=768
  [OK  ] векторная база согласована: 2108 записей x 768
  [OK  ] поиск работает: top1=0.294 0005.0005.0056.1161 …
  итог: 10 ok, 0 предупреждений, 0 блокирующих
```

`top1` около **0.29** — норма для адаптированной базы (`vector_db_adapted_v3`);
для обычной базы там будет около **0.82**. Отсюда и разные пороги:
`FULL_FALLBACK_SIM_THRESHOLD=0.15` для адаптированной. Если порог выше косинусов,
каждый запрос будет уходить в фолбэк по полному классификатору — сборщик комплекта
предупреждает об этом и пишет в шаблон 0.15.

## Частые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `FileMetadataError`, `Couldn't reach huggingface.co` | нет активной `HF_HUB_OFFLINE=1` либо `EMBEDDING_MODEL` указывает на имя репозитория | `--stage pre` покажет обе строки; исправить `.env` |
| `Fatal error in launcher: Unable to create process` | `venv` скопирован с другой машины | удалить `venv`, запустить `install_offline.bat` |
| `ERROR: Could not find a version that satisfies…` при `--no-index` | колёса под другой минор Python | пересобрать комплект с `--python-version <минор со стенда>` |
| `.env` вроде правильный, но сервис берёт значения по умолчанию | файл сохранён как `.env.txt` или в UTF-16 | `--stage pre` детектирует оба случая |
| Сервис стартовал, но классификация падает с 502 | LLM-провайдер требует интернета | перейти на `custom` или `ollama` |
| Каждый запрос уходит в полный классификатор | порог фолбэка выше косинусов базы | `FULL_FALLBACK_SIM_THRESHOLD=0.15` для адаптированной базы |

Копировать: `src/`, `scripts/`, `data/` (кроме тяжёлых артефактов оценки),
`tests/`, `offline_bundle/`, `requirements.txt`, `install_offline.bat`,
`launch.bat`, `.env.example`.

e2e-тестов), `.git/`, `models/e5-finetuned-*` (если не используются).
