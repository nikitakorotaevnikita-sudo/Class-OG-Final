# Интеграция с Directum RX

API-контракт для команды разработки Directum RX. Обновлено 2026-08-12.

**Продуктивный адрес: порт `8010`** (внутри контейнера — 8005). Примеры ниже используют
`localhost:8010`; в примерах для локальной разработки может встречаться 8000 — это тот же API.

Проверить, что сервис готов, до отправки документов:

```bash
curl http://localhost:8010/health
# {"status": "ok", "agent_ready": true, "classifier_entries": 2108}
```

`agent_ready: false` — модель эмбеддингов ещё загружается (первый старт до минуты). Отправлять
запросы в этот момент бессмысленно: `/classify` вернёт 503.

---

## Основной сценарий RX — классификация текста обращения

RX **передаёт текст обращения в запросе**. Сервис классифицирует его напрямую, обращения к OData
при этом не происходит.

```
POST /integration/classify-document
```

**Request:**

```json
{
  "document_id": 26,
  "appeal_text": "Текст обращения гражданина"
}
```

| Поле запроса | Обязательно | Описание |
|---|---|---|
| `appeal_text` | да (основной путь) | текст обращения; классифицируется как есть |
| `document_id` | нет | возвращается в ответе как есть; если `appeal_text` не передан, по нему тело документа берётся из RX по OData (прежний способ вызова) |

**Совместимость.** Прежний вызов только с `document_id` продолжает работать: сервис сам забирает
тело из RX (`IElectronicDocuments({id})` → последняя версия → `Body/$value`) и извлекает текст.
Формат ответа в обоих случаях одинаковый, поэтому переходить на передачу текста можно не
синхронно с обеими сторонами.

**Response (200):**

```json
{
  "document_id": 26,
  "applicant_fio": "Иванов И.И.",
  "summary": "Краткая суть обращения.",
  "reasoning": "Обоснование модели по всем вопросам сплошным текстом (не более 1000 символов).",
  "questions": [
    { "code": "0003.0011.0123.0850", "question": "Арендные отношения в области землепользования" }
  ]
}
```

| Поле | Тип | Описание |
|---|---|---|
| `document_id` | int \| **null** | эхо из запроса; `null`, если RX его не передал |
| `applicant_fio` | string \| **null** | ФИО заявителя, извлечённое из текста; `null`, если не найдено |
| `summary` | string | суть обращения |
| `reasoning` | string | обоснование модели по **всем** вопросам, **одним блоком**, ≤ 1000 символов |
| `questions[].code` | string | код классификатора |
| `questions[].question` | string | наименование кода |

### Что важно учесть на стороне RX

* **`reasoning` — на верхнем уровне, а не внутри каждого вопроса.** При нескольких вопросах
  фрагменты склеиваются, каждый префиксуется своим кодом: `[код] обоснование [код] обоснование`.
  При превышении 1000 символов текст обрезается с «…» на конце.
* **Вопросов может быть несколько.** Обращение с несколькими темами вернёт несколько элементов;
  первый — основной.
* **Код может состоять из 5 сегментов**, а не 4: `0003.0009.0099.0742.0110` — уточняющий код
  уровня L5. Валидацию формата строить как `XXXX.XXXX.XXXX.XXXX[.XXXX]`.
* **Процедурные коды.** Помимо тематических могут приходить:

  | Код | Наименование | Когда | Позиция |
  |---|---|---|---|
  | `0001.0002.0027.0131` | Прекращение рассмотрения обращения | гражданин просит отозвать обращение / прекратить рассмотрение | **первым** элементом |
  | `0001.0002.0027.0125` | Результаты рассмотрения обращения | обращение повторное / ответ не получен | дополнительным элементом |

  Тематический код при этом сохраняется отдельным элементом массива.

### Коды ошибок

| Код | Причина | Действие на стороне RX |
|---|---|---|
| `404` | документ с таким id не найден в RX | проверить id |
| `502` | не удалось получить тело документа из RX | проверить доступность OData, учётные данные, сеть |
| `400` | пустой `appeal_text`, либо запрос без `appeal_text` и без `document_id`, либо документ в RX без извлекаемого текста (скан) | проверить запрос; скан — на распознавание |
| `503` | агент не инициализирован | повторить позже, опрашивать `/health` |
| `500` | ошибка классификации, в том числе недоступность LLM | повторить; при систематическом повторении — смотреть логи сервиса |

### Настройки доступа к RX (нужны только для вызова по `document_id`)

```bash
RX_ODATA_URL=http://172.16.96.98/integration/odata
RX_USER=Administrator
RX_PASSWORD=<пароль>
```

Basic-аутентификация, проверка TLS отключена (самоподписанный сертификат стенда), таймаут запроса
к RX — 60 секунд.

## Альтернатива — классификация готового текста

Если текст уже есть на стороне вызывающей системы, RX-эндпоинт не нужен.

```
POST /classify
```

**Request:**

```json
{
  "appeal_text": "Текст обращения гражданина (до 5000 символов)",
  "appeal_id": "опциональный ID вашей системы"
}
```

**Response (200):**

```json
{
  "log_id": "uuid-верификации",
  "appeal_id": "ваш-ID",
  "vid_obrascheniya": "Жалоба",
  "tip_obrascheniya": "Индивидуальное",
  "is_ustnoe": false,
  "questions": [
    {
      "question_text": "Выявленный вопрос из обращения",
      "code": "0005.0005.0056.1160",
      "name": "Обращение с твёрдыми коммунальными отходами",
      "level": 4,
      "full_path": "Жилищно-коммунальная сфера / Обращение с ТКО / ...",
      "predmet_vedeniya": "Вопрос местного значения",
      "confidence": 0.87,
      "reasoning": "Обоснование выбора",
      "alternatives": [
        { "code": "...", "name": "...", "full_path": "..." }
      ]
    }
  ],
  "overall_confidence": 0.87,
  "needs_verification": false,
  "operator_card": "Текстовая карточка для оператора",
  "was_truncated": false,
  "llm_provider": "ario",
  "llm_model": "Qwen/Qwen3.6-35B-A3B",
  "full_fallback_used": false
}
```

Этот ответ богаче RX-контракта: `alternatives` (топ-3 подсказки оператору), `confidence` по
каждому вопросу, `full_path`, `predmet_vedeniya`, `operator_card`.

Служебные поля:

| Поле | Значение |
|---|---|
| `was_truncated` | текст был длиннее 5000 символов и обрезан |
| `full_fallback_used` | сработал повторный проход по полному классификатору (ретривер промахнулся) |
| `llm_provider`, `llm_model` | какой моделью выполнена классификация |
| `log_id` | идентификатор для последующего `POST /verify` |

### Классификация файла

```
POST /classify/file
```

`multipart/form-data`, поле `file`. Форматы — `.txt` и `.pdf` (**только с текстовым слоем**, сканы
не распознаются), максимум 5 МБ. Ответ — тот же `ClassifyResponse`; при обрезке длинного текста
вернётся `was_truncated: true`.

## Прочие эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | статус агента и число записей классификатора |
| `POST` | `/verify` | верификация результата оператором (см. ниже) |
| `GET` | `/examples` | 10 тестовых обращений |
| `GET` | `/classifier/search` | поиск по классификатору |
| `GET` | `/stats` | статистика по логу обращений |
| `GET` | `/api/llm/options` | доступные LLM-провайдеры и модели |
| `GET` | `/docs` | Swagger UI с актуальными схемами |

### POST /verify

```bash
curl -X POST http://localhost:8010/verify \
  -H "Content-Type: application/json" \
  -d '{"log_id": "<uuid>", "action": "confirm"}'
```

`action`: `confirm` | `correct` | `reject`. Для `correct` передать выбранные оператором коды:

```json
{ "log_id": "<uuid>", "action": "correct", "operator_codes": ["0005.0005.0056.1160"] }
```

Верификации накапливаются в `data/appeals_log.jsonl` и используются для дообучения эмбеддера.

## Поля для карточки обращения в Directum

Из ответа `/integration/classify-document`:

| Поле Directum | Источник |
|---|---|
| Код вопроса | `questions[0].code` |
| Наименование вопроса | `questions[0].question` |
| ФИО заявителя | `applicant_fio` |
| Суть обращения | `summary` |
| Обоснование ИИ | `reasoning` |

Из ответа `/classify` дополнительно доступны:

| Поле Directum | Источник |
|---|---|
| Вид обращения | `vid_obrascheniya` |
| Тип обращения | `tip_obrascheniya` |
| Предмет ведения | `questions[0].predmet_vedeniya` |
| Уровень классификатора | `questions[0].level` |
| Уверенность | `overall_confidence` |
| Требует верификации | `needs_verification` |

## Лимиты

- Максимальная длина текста: **5000 символов** (при превышении — обрезка, флаг `was_truncated`)
- Максимальный размер файла: **5 МБ**
- Форматы файлов: `.txt`, `.pdf` (только текстовые, сканы без текстового слоя не поддерживаются)
- Длина `reasoning` в RX-контракте: **1000 символов**
- Таймаут обращения сервиса к OData RX: 60 секунд
- Обработка **последовательная**: запросы выполняются по одному, параллельной обработки нет
  (см. `docs/EPIC_load-scaling.md`). Для потоковой загрузки это учитывать при расчёте времени.
