# Руководство пользователя

## Для кого и о чём этот документ

Документ для оператора или специалиста органа власти, который работает с обращениями граждан.
Программировать не нужно. Здесь описано, как запустить и остановить сервис, как классифицировать
обращение, как проверить результат и что делать, если что-то не работает.
Сервис уже установлен администратором. Установка и настройка описаны в [Setup_instruction.md](Setup_instruction.md).

## 1. Что делает сервис

Сервис читает текст обращения гражданина и подсказывает, как его зарегистрировать:

- какой это **вид обращения** по Федеральному закону № 59-ФЗ: жалоба, заявление или предложение;
- какой это **тип обращения**: индивидуальное, коллективное или анонимное;
- какие **вопросы** гражданин поднимает (в одном письме их может быть несколько);
- какой **код Общероссийского классификатора вопросов** подходит к каждому вопросу.
  Код состоит из четырёх групп цифр, например `0005.0005.0056.1160`.

Сервис работает в два шага. Сначала он ищет в классификаторе (2108 записей) несколько десятков
похожих по смыслу пунктов. Затем **LLM** (большая языковая модель — программа, которая понимает
текст на естественном языке) читает обращение, выбирает лучший код для каждого вопроса и
объясняет свой выбор.

Сервис только **предлагает** ответ. Решение принимает человек: оператор подтверждает
или исправляет результат. Исправления оператора сохраняются, и на них сервис со временем
учится лучше (это называется **дообучение**).

## 2. Как выглядит результат

Пример. Гражданин пишет: «Прошу отремонтировать дорогу во дворе дома №5, яма не даёт проехать».
Сервис может вернуть такой результат:

| Поле на экране | Пример значения | Что означает |
|---|---|---|
| Вид обращения | Заявление | Жалоба, заявление или предложение по 59-ФЗ |
| Тип | Индивидуальное | Индивидуальное, коллективное или анонимное |
| Код | `0003.0009.0097.0699` | Код вопроса по классификатору |
| Тема | Благоустройство и ремонт подъездных дорог, в том числе тротуаров | Что именно означает код |
| Путь | Экономика / Хозяйственная деятельность / Градостроительство и архитектура / … | Где код находится в классификаторе: раздел → тематика → тема → вопрос |
| Обоснование | Короткий текст модели | Почему выбран этот код |
| Уверенность | 82% | Насколько модель уверена в коде |

**Уверенность** — число от 0 до 100%. Полоска под вопросом окрашена так:

| Цвет | Уверенность | Как действовать |
|---|---|---|
| Зелёный | 80% и выше | Скорее всего, код верный. Достаточно быстро проверить |
| Жёлтый | от 65% до 79% | Код вероятный, но стоит посмотреть альтернативы |
| Красный | ниже 65% | Модель сомневается. Проверьте внимательно |

**Общая уверенность** — среднее по всем вопросам обращения. Если она ниже порога
(по умолчанию 65%, настройка `MIN_CONFIDENCE`), на экране появляется жёлтая плашка
**«Требует верификации оператором»**. Верификация — это проверка результата человеком.
Плашка не означает ошибку: она говорит, что это обращение нужно проверить особенно внимательно.

## 3. Запуск и остановка

Сервис состоит из нескольких частей: веб-интерфейс (API), база данных и **воркеры** (программы,
которые выполняют классификацию). **Очередь задач** — список обращений, которые ждут
обработки, — хранится в той же базе данных: API записывает туда обращение, свободный воркер
забирает его, классифицирует и записывает результат. Скрипты запуска поднимают всё сразу,
отдельно ничего включать не нужно.

Для работы нужна запущенная программа **Docker** (на Windows — Docker Desktop).
В ней работает база данных.

Администратор мог настроить один из вариантов:

- **всё на одном компьютере** — база в Docker, сам сервис и воркеры в отдельных окнах. Его
  запускает меню `launch.bat`, пункт [1]. Это основной вариант, он описан ниже;
- **воркеры на других компьютерах** — на главном компьютере запускается сервис без воркеров
  (пункт [2]), а на других компьютерах — только воркеры (пункт [3]). Так делают, когда
  обращений много и одного компьютера не хватает;
- **режим Docker** — всё целиком в Docker. Запуск `start.cmd docker`, остановка `stop.cmd docker`.

Если не знаете, какой вариант у вас, спросите администратора.

### 3.1. Windows: запуск

1. Убедитесь, что Docker Desktop запущен: в его окне должно быть написано «Engine running».
2. Откройте папку с сервисом и дважды щёлкните `launch.bat`.
3. Появится меню:

   ```
   ================================================
     Citizens Appeals Classification Agent
   ================================================
     [1] Start everything: API + workers (port 8010)
     [2] Start without workers: API only (port 8010)
     [3] Start workers only (DB = DATABASE_URL in .env)
     [4] Start everything on another port
     [5] Verify the installation
     [6] Run tests
     [7] Classify manually (type appeal text)
     [8] Operator mode  (verify + fine-tuning)
     [9] Select LLM provider
   ================================================
     Current LLM: ario
   ```

4. Нажмите `1` и Enter (или просто Enter — это тоже пункт 1).
5. Подождите. Запуск идёт по шагам `[1/4]` … `[4/4]`. Откроются отдельные окна
   с заголовками `classifier-api` и `classifier-worker-1`, `classifier-worker-2`.
   **Не закрывайте эти окна** — в них работает сервис. Каждое окно воркера обрабатывает одно
   обращение за раз; сколько окон воркеров открыть, задаёт администратор.
6. В конце должны появиться строки:

   ```
   OK: API is up, database reachable, a classify worker is ready: http://localhost:8010/health
   Back office: http://localhost:8010/backoffice    Stop: stop.cmd all
   ```

   Это значит, что сервис готов. Если вместо этого появилась строка `ERROR: ...`,
   смотрите раздел [11](#11-частые-вопросы-и-проблемы).

Что означают остальные пункты меню:

| Пункт | Что делает |
|---|---|
| [1] Start everything | Запускает базу, сервис и воркеры на порту 8010 (или на порту из настройки `API_PORT`) |
| [2] Start without workers | Запускает базу и сервис **без воркеров**. Обращения принимаются, но ждут в очереди, пока не запустятся воркеры на другом компьютере. В конце появится предупреждение `WARNING: no workers are running - jobs wait in the queue...` — при этом варианте так и должно быть |
| [3] Start workers only | Запускает только окна воркеров. Нужен на дополнительном компьютере, который администратор подключил к базе главного компьютера. В конце: `Worker windows: classifier-worker-*    Stop: stop.cmd worker` |
| [4] Start everything on another port | То же, что [1], но спросит номер порта. Нужно, если 8010 занят |
| [5] Verify the installation | Проверяет, что всё установлено. Пригодится перед звонком администратору |
| [6] Run tests | Технические тесты. Оператору обычно не нужны |
| [7] Classify manually | Разовая классификация в консоли, см. [раздел 9](#9-работа-из-консоли) |
| [8] Operator mode | Режим оператора в консоли, см. [раздел 9](#9-работа-из-консоли) |
| [9] Select LLM provider | Выбор языковой модели: `ario` (основная), `custom`, `ollama`, `groq`, `gemini`. Меняйте только по указанию администратора |

### 3.2. Windows: остановка

1. Откройте командную строку в папке сервиса (в Проводнике: адресная строка → `cmd` → Enter).
2. Выполните:

   ```
   stop.cmd
   ```

3. Окна `classifier-*` закроются, база остановится. Появится строка
   `OK: classifier processes and windows closed (if any were open).`

Данные (обращения, результаты, проверки) при остановке **не удаляются**. Обращение, которое
воркер не успел доделать, тоже не пропадает: оно останется в очереди и будет обработано при
следующем запуске.

На компьютере, где работают только воркеры (пункт [3]), остановка — `stop.cmd worker`: закроются
только окна воркеров. Если после сбоя окно воркера осталось открытым с текстом ошибки,
закройте его вручную.

Если администратор настроил режим Docker: запуск — `start.cmd docker`, остановка — `stop.cmd docker`.

### 3.3. Linux: запуск и остановка

1. Откройте терминал в папке сервиса.
2. Выполните `./launch.sh`. Появится меню с теми же пунктами, что и на Windows, только на
   русском:

   ```
   [1] Запустить всё: API + воркеры (порт 8010)
   [2] Запустить без воркеров: только API (порт 8010)
   [3] Запустить только воркеры (база — DATABASE_URL в .env)
   [4] Запустить всё на другом порту
   [5] Проверить установку
   [6] Тесты
   [7] Разовая классификация (ввести текст обращения)
   [8] Режим оператора (верификация + дообучение)
   [9] Выбрать провайдера LLM
   ```

3. Нажмите Enter (пункт 1). В конце появится строка
   `бэк-офис: http://localhost:8010/backoffice   остановка: ./stop.sh all`.
   Отдельных окон на Linux нет: сервис и воркеры работают в фоне, их журналы лежат в папке
   `run/` (`run/api.log`, `run/worker-classify-1.log` и так далее).
4. Чтобы остановить сервис, выполните `./stop.sh`. На компьютере только с воркерами —
   `./stop.sh worker`.

## 4. Как проверить, что сервис работает

Откройте в браузере на том же компьютере (если сервис на другом компьютере —
замените `localhost` на его адрес):

| Адрес | Что там |
|---|---|
| http://localhost:8010/ | Классификация обращений |
| http://localhost:8010/backoffice | Бэк-офис: статистика, модели, настройки |
| http://localhost:8010/static/historical.html | Загрузка исторических данных и дообучение |
| http://localhost:8010/health | Короткая проверка состояния |

Страница `/health` показывает строку вида:

```json
{"status":"ok","agent_ready":true,"classifier_entries":2108,"db":true}
```

| Поле | Что значит | Если плохо |
|---|---|---|
| `db: true` | База данных доступна. В ней же хранится очередь задач | `false` — база не запущена. Проверьте Docker |
| `agent_ready: true` | Хотя бы один воркер подключён к базе и готов классифицировать (на этом или на другом компьютере) | `false` — воркеры ещё загружаются (подождите 1–2 минуты), их окна закрыты или сервис запущен без воркеров (пункт [2]), а воркеры на других компьютерах не запущены. Обращения при этом не теряются: они ждут в очереди |
| `classifier_entries` | Сколько записей классификатора в базе | `0` — база пустая, звоните администратору |

Если страница не открывается совсем, смотрите [раздел 11](#11-частые-вопросы-и-проблемы).

## 5. Классификация обращения в веб-интерфейсе

Откройте http://localhost:8010/. Слева — меню «Классификация» и «Исторические данные»,
справа вверху — кнопка «Бэк-офис». В левой колонке «Сводка» показано, сколько результатов
уже проверено и сколько ждёт проверки.

### 5.1. Блок «Быстрый ввод»

| Поле | Что делать |
|---|---|
| Пример обращения | Выберите готовый пример, чтобы посмотреть, как работает сервис. Текст подставится в поле ниже |
| LLM provider | Какая языковая модель обработает обращение. Обычно оставляйте как есть (Ario) |
| LLM model | Название модели. Подставляется само при выборе провайдера |

Справа от заголовка видна строка `LLM: …` — какая модель выбрана сейчас.
Выбор провайдера и модели здесь действует только на ваш запрос и не меняет общие настройки.

### 5.2. Блок «Обращение»

Текст можно ввести одним из двух способов.

- **Вставить текст.** Скопируйте текст обращения в поле «Текст обращения».
- **Загрузить файл.** В поле «Файл» выберите файл формата **TXT или PDF размером до 5 МБ**.
  PDF должен содержать текст. Отсканированный PDF (картинка без текста) сервис не прочитает:
  появится ошибка «PDF является сканом без текста. Используйте OCR перед загрузкой».

Если выбран файл, используется файл, а текст в поле не учитывается.

### 5.3. Запуск

1. Нажмите **«Классифицировать»**.
2. Появится надпись «Классификация...». Обычно это занимает от нескольких десятков секунд
   до нескольких минут — модель читает обращение целиком. Не нажимайте кнопку повторно.
3. Появится блок «Результат».

Кнопка **«Очистить»** стирает текст, файл и результат.

### 5.4. Что показано в результате

- **Общая уверенность** — под заголовком «Результат».
- **Вид обращения**, **Тип**, **LLM provider**, **LLM model** — карточки вверху.
- Плашка **«Требует верификации оператором»**, если общая уверенность ниже порога.
- Для каждого вопроса — блок «Вопрос 1 из 3» (или просто «Вопрос», если он один):
  - **Код** и **Тема** — выбранный пункт классификатора;
  - **Путь** — где этот пункт находится в классификаторе;
  - **Ведение** — предмет ведения по оценке модели: «Вопрос местного значения», «Предмет ведения
    Российской Федерации», «Предмет ведения субъектов Российской Федерации» или «Предмет совместного
    ведения…». Поле может быть пустым;
  - **Обоснование** — почему модель выбрала этот код;
  - **Альтернативы** — другие подходящие коды с их уверенностью. Если основной код не подходит,
    правильный часто есть среди альтернатив;
  - полоска **Уверенность** с цветом (см. [раздел 2](#2-как-выглядит-результат)).
- **JSON ответа** — свёрнутый блок с полным ответом сервиса. Оператору обычно не нужен,
  но его можно скопировать администратору при разборе проблемы.

## 6. Проверка результата: подтвердить, исправить, отклонить

Под результатом есть три кнопки. Каждая проверка сохраняется в базе и учитывается при дообучении.

| Кнопка | Когда нажимать | Что произойдёт |
|---|---|---|
| **Подтвердить** (зелёная) | Коды выбраны верно | Результат отмечается как подтверждённый. Сервис запомнит, что ответ был правильным |
| **Исправить** (жёлтая) | Код неверный, вы знаете правильный | Откроется форма исправления (см. ниже) |
| **Отклонить** (красная) | Результат непригоден: это не обращение, текст испорчен и т. п. | Результат отмечается как отклонённый и для обучения не используется |

Как исправить код:

1. Нажмите **«Исправить»**.
2. В поле **«Правильный код вопроса»** введите код полностью, например `0005.0005.0051.1103`.
   В веб-интерфейсе вводится один код. Несколько кодов можно указать в консольном режиме оператора
   ([раздел 9](#9-работа-из-консоли)).
3. Поле **«Пояснение к коду»** можно оставить пустым. Если заполняете — напишите
   не меньше 10 символов, почему подходит этот код. Пример: «Ремонт внутридомовых дорог относится
   к содержанию придомовой территории». Пояснение помогает сервису в будущем находить этот код.
4. Нажмите **«Сохранить исправление»**. Появится сообщение «Исправление сохранено».

После любой из трёх кнопок результат скрывается, а счётчик «Верифицировано» в левой колонке
увеличивается. Когда число проверенных достигнет порога (по умолчанию 50), появится сообщение
«Порог дообучения достигнут».

## 7. Бэк-офис

Бэк-офис — служебная страница для просмотра статистики и настроек:
http://localhost:8010/backoffice. В нём две вкладки: **«Статистика»** и **«Настройки»**.

### 7.1. Вход

Отдельной страницы входа нет: бэк-офис открывается сразу. Логин и пароль браузер спросит
только при активации версии модели (см. 7.3). Их задаёт администратор
(настройки `BACKOFFICE_USER` и `BACKOFFICE_PASSWORD`).

### 7.2. Вкладка «Статистика»

Вверху четыре показателя:

| Показатель | Что означает |
|---|---|
| Всего классификаций | Сколько обращений обработал сервис |
| Верификаций | Сколько результатов проверили операторы (подтверждено + исправлено) |
| Доля подтверждённых | Какую часть проверенных результатов операторы подтвердили без исправлений. Это главный признак качества |
| Средняя уверенность | Средняя уверенность модели по всем результатам |

Ниже графики:

- **Распределение уверенности** — сколько обращений получили ту или иную уверенность.
  Если столбцы сдвинуты влево (низкая уверенность), операторам придётся проверять больше.
- **Топ-10 кодов классификатора** — самые частые темы обращений.
- **Частота использования за 30 дней** — сколько обращений обработано по дням.
- **Статистика по IP-адресам** — с каких компьютеров приходят запросы.

### 7.3. Таблица «Модели»

Здесь перечислены версии **модели поиска** (она находит похожие пункты классификатора;
после каждого дообучения появляется новая версия).

| Колонка | Что означает |
|---|---|
| Версия | Номер версии. 0 — исходная модель |
| Модель | Где хранится модель |
| Recall@5 до / после | Качество поиска до и после дообучения: как часто правильный код попадает в пятёрку лучших. Чем больше, тем лучше |
| Примеров | Сколько примеров использовано при обучении |
| Обучена | Дата и время обучения |
| Статус | «Активна» — эта версия работает сейчас. У остальных — кнопка «Активировать» |

Новая версия становится активной сама, если качество поиска выросло. Кнопка **«Активировать»**
нужна, чтобы вручную включить другую версию, например вернуться к прежней.
После нажатия браузер попросит подтвердить действие, а затем логин и пароль бэк-офиса.
Перезапускать сервис не нужно: новая версия начнёт работать со следующего обращения.
Делайте это только по согласованию с администратором.

### 7.4. Вкладка «Настройки»

Здесь меняются подключения сервиса. Обычно этим занимается администратор, но оператору
полезно знать, что здесь есть.

| Группа | Поля |
|---|---|
| Модель LLM | Провайдер; модель, адрес и API-ключ Ario; адрес, модель и ключ своего сервера (custom); модель и ключ Groq; ключ Gemini; модель и адрес Ollama |
| Directum RX | OData URL, пользователь, пароль для подключения к RX |
| Очередь | Ожидание синхронного ответа, с — сколько секунд сервис ждёт результат классификации (по умолчанию 1800, то есть 30 минут) |

Кнопки:

| Кнопка | Что делает |
|---|---|
| Сохранить | Записывает изменённые поля. Изменения применяются сразу, без перезапуска. Перед записью сохраняется резервная копия |
| Проверить связь с LLM | Пробует обратиться к выбранной языковой модели и показывает результат |
| Проверить подключение к RX | Пробует подключиться к Directum RX |
| Сбросить изменения | Возвращает значения, которые сохранены сейчас |

Ключи и пароли показаны маской. Пустое поле пароля означает «оставить как было».

## 8. Исторические данные и дообучение

Страница http://localhost:8010/static/historical.html (пункт меню «Исторические данные»).
**Исторические данные** — обращения прошлых лет, которым специалисты уже присвоили коды.
Сервис учится на них так же, как на проверках операторов.

### 8.1. Загрузка файла

Подходят файлы **XLSX, XLS, CSV или JSON размером до 50 МБ**. В файле обязательны две колонки:

| Что | Допустимые названия колонки |
|---|---|
| Текст обращения | `appeal_text`, `text`, `текст`, `обращение` |
| Код классификатора | `assigned_code`, `code`, `код`, `код_классификатора` |
| Специалист (необязательно) | `specialist`, `specialist_name`, `специалист`, `фио` |
| Дата (необязательно) | `date`, `дата`, `registration_date` |

JSON должен содержать список записей с такими полями.

1. Перетащите файл в область «Перетащите файл сюда» или щёлкните по ней и выберите файл.
2. Появится «Загрузка и валидация...». Сервис проверит каждый код по классификатору.
3. Откроется «Результат валидации»: сколько записей **Валидных**, **С ошибками** и **Всего**.
   Ниже — список ошибок вида «Строка 12: 0005.0005 — Неверный формат кода» или
   «Код не найден в классификаторе» и предпросмотр первых 5 записей.
4. Нажмите **«Загрузить валидные»** — сохранятся только записи без ошибок.
   Появится «Файл успешно сохранён». Повторно загруженные одинаковые записи пропускаются.
   Кнопка **«Отмена»** возвращает к выбору файла, ничего не сохраняя.

### 8.2. Запуск дообучения

В блоке «Дообучение модели» показано, сколько исторических записей уже в базе.

1. Нажмите **«Запустить дообучение»** и подтвердите в окне браузера.
2. Сервис учится на исторических записях и на проверках операторов вместе.
   Появится «Дообучение модели может занять 10-15 минут...». Страницу можно не закрывать —
   статус обновляется сам каждые 3 секунды.
3. Возможные сообщения:

| Сообщение | Что значит |
|---|---|
| Дообучение поставлено в очередь | Задача ждёт свободного обработчика |
| Дообучение модели запущено | Идёт обучение |
| Модель дообучена (или итоговый текст) | Готово. Новая версия появится в таблице «Модели» бэк-офиса |
| Ошибка: … | Обучение не выполнено. Передайте текст ошибки администратору |
| Дообучение уже выполняется | Предыдущий запуск ещё не закончился. Дождитесь его |

Дообучение выполняет отдельный обработчик — **воркер дообучения**. Пункт [1] меню `launch.bat`
его не запускает. Если статус долго стоит на «Дообучение поставлено в очередь», попросите
администратора запустить сервис с воркером дообучения (`start.cmd all --training`).
Если окно воркера дообучения закрыли во время обучения, через минуту-две появится ошибка
«воркер дообучения пропал, запустите дообучение заново» — запустите дообучение ещё раз.

## 9. Работа из консоли

Эти режимы нужны, если веб-интерфейс недоступен или для быстрой проверки.
Они загружают модель прямо в окно консоли, поэтому первый запуск занимает около минуты.
База данных при этом должна быть запущена.

**Режим оператора** — пункт [8] меню `launch.bat` или `launch.sh`.

1. Введите текст обращения. Чтобы закончить ввод, нажмите Enter на пустой строке.
2. Сервис покажет карточку результата.
3. Выберите `[1] Подтвердить   [2] Исправить   [3] Отклонить`.
4. При исправлении введите правильные коды через запятую, например
   `0005.0005.0056.1160, 0005.0005.0063.1188`, затем при желании пояснение (минимум 10 символов
   или Enter, чтобы пропустить).
5. На вопрос «Следующее обращение? (Enter — да, q — выйти)» нажмите Enter или `q`.

Когда проверенных записей станет не меньше порога (50), режим предложит
«Запустить дообучение эмбеддинговой модели? (y/n)».

**Разовая классификация** — пункт [7] меню `launch.bat` или `launch.sh`.
Введите текст, получите результат, проверки не сохраняются. Выход — `q`.

## 10. Работа через Directum RX

Сервис можно вызывать прямо из Directum RX. Как именно запускается классификация в карточке
(кнопкой или автоматически при регистрации), настраивают специалисты RX. Со стороны сервиса
это выглядит так:

1. RX передаёт сервису текст обращения (или номер документа — тогда сервис сам забирает
   текст документа из RX).
2. Сервис ставит обращение в очередь и классифицирует его.
3. RX получает результат и заполняет карточку:
   - **ФИО заявителя** и **электронная почта**, если они есть в тексте;
   - **краткое содержание** обращения;
   - **вопросы** — список «код — название пункта классификатора». Если несколько вопросов
     получили один и тот же код, в RX придёт одна строка;
   - **обоснование** модели одним текстом (до 1000 символов).

RX может ждать ответа сразу (до 30 минут по умолчанию) или забрать результат позже по номеру
задачи. Задача проходит статусы: `queued` (ждёт в очереди), `running` (обрабатывается),
`done` (готово), `error` (ошибка).

Через RX сервис возвращает коды, но не показывает уверенность и кнопки проверки.
Проверяйте и при необходимости исправляйте коды в карточке RX.

Если документ в RX — скан без текстового слоя, сервис его не прочитает и вернёт ошибку
«скан без текстового слоя. Распознавание (OCR) сервис не выполняет».
Если в очереди уже 100 обращений, новые временно не принимаются («Очередь заполнена») —
повторите позже.

Технические подробности для специалистов RX — в [arch.md](arch.md) и на странице
http://localhost:8010/docs.

## 11. Частые вопросы и проблемы

**Страница http://localhost:8010/ не открывается.**

1. Проверьте, что сервис запущен: на Windows должны быть открыты окна `classifier-api`
   и `classifier-worker-1`. Если их нет — запустите сервис ([раздел 3](#3-запуск-и-остановка)).
2. Если окно `classifier-api` открыто, посмотрите в нём последние строки — там будет причина ошибки.
3. Возможно, сервис запущен на другом порту. Посмотрите строку `Back office: http://localhost:…`
   в окне, где запускали `launch.bat`.
4. Если сервис на другом компьютере, вместо `localhost` нужен адрес этого компьютера.

**При запуске появилось `ERROR: the Docker engine does not respond`**
(на Linux — «движок Docker не отвечает»).

Docker не запущен или завис.

1. Запустите Docker Desktop. Если он уже запущен — в его окне выберите Troubleshoot → Restart.
2. Дождитесь надписи «Engine running».
3. Запустите сервис снова.

**`ERROR: port 8010 is already in use`.**

Сервис уже запущен — раньше или в режиме Docker. Остановите его (`stop.cmd` или
`stop.cmd docker`) и запустите снова. Либо выберите пункт [4] меню и укажите другой порт,
например 8011.

**Классификация идёт очень долго.**

Обычно ответ приходит за десятки секунд, длинное обращение с многими вопросами — за несколько минут.
Обращения обрабатываются по очереди: если их много, ваше ждёт своей очереди.
Не нажимайте «Классифицировать» повторно. Если ответа нет дольше 30 минут, появится ошибка
«Классификация не завершилась за 1800 с …». Проверьте http://localhost:8010/health: если
`agent_ready: false`, воркеры не работают — перезапустите сервис (или воркеры на другом
компьютере, если они у вас там).

**Ошибка классификации, связанная с LLM** (сообщение «Ошибка классификации: …»
с упоминанием timeout, connection или provider).

Основная модель Ario доступна только из корпоративной сети или через **VPN**.

1. Проверьте, что VPN подключён.
2. Откройте бэк-офис → «Настройки» → нажмите «Проверить связь с LLM».
3. Если проверка не проходит, сообщите администратору. Он может временно переключить
   сервис на другую модель.

**Почти все результаты с низкой уверенностью или с плашкой «Требует верификации оператором».**

Это не ошибка: модель честно сообщает о сомнениях. Так бывает с короткими, нечёткими
или многотемными обращениями.

1. Посмотрите блок «Альтернативы» — правильный код часто там.
2. Исправляйте неверные коды через «Исправить» и добавляйте пояснение.
   Чем больше проверок, тем лучше станет сервис после дообучения.
3. Если низкая уверенность держится долго, сообщите администратору — можно запустить дообучение
   ([раздел 8](#8-исторические-данные-и-дообучение)).

**Ошибка «PDF является сканом без текста».**

Файл — картинка. Распознайте его в программе для OCR (распознавания текста)
или скопируйте текст вручную в поле «Текст обращения».

**В /health написано `db: false`.**

База не запущена (очередь задач хранится в ней же). Проверьте, что Docker работает, и
перезапустите сервис: `stop.cmd`, затем снова `launch.bat` → [1].

**Окно воркера закрылось само или показывает ошибку.**

Обращение, которое этот воркер обрабатывал, не потеряется: примерно через минуту его возьмёт
другой воркер. Если окно осталось открытым с текстом ошибки, закройте его вручную и передайте
текст ошибки администратору. Чтобы вернуть воркер, перезапустите сервис (`stop.cmd`, затем
`launch.bat` → [1]).
