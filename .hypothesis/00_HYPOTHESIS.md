# Гипотеза проекта

**Дата:** 2026-04-25
**Автор:** Никита Коротаев
**Статус:** Черновик

---

## Краткое описание

ИИ-агент автоматической классификации обращений граждан по Федеральному закону № 59-ФЗ и Общероссийскому классификатору вопросов обращений граждан (v4, 2108 позиций) для интеграции с системой Directum RX 25.3.

---

## Проблема

**Что не работает сейчас?**

Операторы Directum RX вручную классифицируют каждое входящее обращение гражданина: выбирают вид обращения (жалоба, заявление, предложение), тип (устное/письменное) и один или несколько кодов из 2108-позиционного классификатора. Это рутинная, трудоёмкая и субъективная операция — операторы допускают ошибки и тратят на неё значительное время.

**Кто сталкивается с этой проблемой?**

Операторы органов государственной власти и муниципального управления, работающие с входящими обращениями граждан в Directum RX. Специалисты канцелярий, отделов по работе с обращениями.

**Масштаб проблемы:**

50–200 пользователей (операторы одного-нескольких ведомств на пилоте).

**Насколько это критично?**

Высокая — ошибочная классификация ведёт к нарушению сроков ответа (59-ФЗ), маршрутизации не к тому исполнителю, статистическим искажениям.

**Как пользователи справляются сейчас?**

Полностью вручную: открывают справочник классификатора (PDF/Excel), ищут подходящий код, вводят его в карточку Directum RX. Занимает 2–10 минут на обращение.

---

## Предлагаемое решение

**Что мы хотим построить?**

Веб-интерфейс для демонстрации ИИ-агента классификации: оператор вставляет текст обращения (или выбирает готовый пример), получает карточку классификации с кодами, уверенностью и обоснованием, затем подтверждает, исправляет или отклоняет результат. Верификации накапливаются для последующего дообучения модели.

**Как это решит проблему?**

Двухэтапный пайплайн: (1) семантический поиск по 2108 позициям классификатора (multilingual-e5-base, cosine similarity) даёт топ-10 кандидатов; (2) LLM (Groq llama-3.3-70b-versatile) выбирает лучший код, определяет вид/тип обращения и обосновывает решение. Оператор видит готовый результат за 3–8 секунд вместо ручного поиска.

**Что должно получиться в итоге?**

Работающий прототип: веб-UI с демонстрационными примерами обращений, карточкой классификации, кнопками верификации [Подтвердить / Исправить / Отклонить] и бэк-офисом с метриками использования.

**Сценарии использования:**

1. Оператор открывает браузер → выбирает пример из dropdown → нажимает «Классифицировать» → видит код, название, путь в иерархии, уверенность → нажимает «Подтвердить» → запись уходит в лог.
2. Оператор вставляет произвольный текст обращения → агент классифицирует → оператор нажимает «Исправить», вводит верный код → в лог записывается пара (текст, исправленный код) для дообучения.
3. Оператор открывает `/backoffice` → видит статистику запросов, распределение уверенности, топ кодов.
4. Многовопросное обращение (жалоба сразу на несколько тем) → агент возвращает несколько вопросов, каждый со своим кодом.

**Источники данных:**

- `data/classifier_flat.json` — 2108 позиций классификатора (уже есть)
- `data/vector_db/` — векторная БД (numpy embeddings + metadata.json, уже есть)
- `data/appeals_log.jsonl` — лог верификаций (накапливается в процессе работы)
- `data/test_appeals.json` — 10 готовых примеров обращений для демо (уже есть)

## Интеграция с Directum RX

> Интеграция с Directum RX через API — **не входит в MVP-прототип**. Прототип работает автономно как веб-демо. Интеграция планируется на следующем этапе после подтверждения гипотезы.

Планируемая интеграция (post-MVP):
- REST API: `POST /classify` принимает текст → возвращает код и вид обращения → Directum RX заполняет карточку автоматически.
- Целевая система: Directum RX 25.3.

## Критерии успеха

**Как поймём, что гипотеза подтвердилась?**

- [ ] Агент правильно классифицирует ≥85% тестовых обращений (top-1 accuracy на 10 демо-примерах)
- [ ] Среднее время классификации <10 секунд
- [ ] Операторы в состоянии самостоятельно пройти цикл [классифицировать → верифицировать] без инструкций
- [ ] Многовопросные обращения корректно разбиваются на отдельные вопросы с кодами
- [ ] Бэк-офис доступен и отображает актуальные метрики

**Метрики (конкретные числа):**

- Top-1 точность на демо-примерах: ≥85%
- Время от отправки текста до получения карточки: <10 сек
- Доля обращений с `needs_verification=True` при уверенности <0.65: корректно проставляется
- Покрытие тестами: ≥70% (pytest)

**Пилотная группа:**

Пилот планируется с 5–10 операторами одного ведомства после успешного демо прототипа.

## Ограничения

**Что НЕ входит в прототип:**

- Интеграция с Directum RX API (только автономное веб-демо)
- Авторизация пользователей (только Basic Auth для бэк-офиса)
- Работа с вложениями и файлами (только текст обращения)
- Дообучение модели в интерфейсе (fine-tuning запускается отдельно через `src/finetune_model.py`)
- Многоязычность (только русский язык)

**Технические ограничения:**

- Python 3.11 (не 3.12+) — ML-зависимости несовместимы с 3.12+
- LLM: Groq API (llama-3.3-70b-versatile) вместо OpenAI — осознанное отклонение от шаблона, обусловленное стоимостью и скоростью; интерфейс совместим с OpenAI SDK
- Векторная БД: numpy + JSON (ChromaDB отклонён из-за несовместимости с Windows/Python 3.11)
- numpy < 2.0 (numpy 2.x ломает старые зависимости)

**Дедлайн:** нет жёсткого дедлайна, MVP-демо как можно скорее.

## Предположения

- У пользователей есть браузер и сетевой доступ к хосту с прототипом
- Groq API доступен и ключ задан в `.env`
- Векторная БД уже собрана (`data/vector_db/` существует)
- Операторы знакомы с понятием «код классификатора» и смогут ввести исправление вручную
- 10 демо-примеров достаточно для первичной демонстрации

## Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| LLM даёт неверный код с высокой уверенностью | Средняя | Высокое | Оператор верифицирует; порог уверенности 0.65 сигнализирует о сомнениях |
| Groq API недоступен / лимит запросов | Средняя | Высокое | Retry-логика; fallback — показать топ-10 кандидатов без LLM |
| Векторная БД не собрана (нет `data/vector_db/`) | Низкая | Критическое | Инструкция в QUICKSTART.md; `build_vectordb.py` запускается при старте |
| Docker не поднимается на Windows из-за зависимостей | Средняя | Среднее | Альтернатива — запуск через venv напрямую |
| Покрытие тестами <70% | Средняя | Среднее | Дописать unit-тесты для сервисов |
