## 1. Что нужно сделать (суть задачи)

MVP-сервис интеграции: RX-процесс дёргает наш REST-эндпоинт, передавая **id
документа**. Сервис сам тянет документ из RX по OData, извлекает текст,
классифицирует и возвращает JSON:

```
POST /integration/classify-document
Запрос:  { "document_id": 26 }
Ответ:   {
  "document_id": 26,
  "applicant_fio": "Иванов И.И.",        // ФИО заявителя, формат «Фамилия И.О.» или null
  "summary": "краткая суть ≤250 символов",
  "questions": [ { "code": "0001.0002.0015.0042", "question": "наименование текстом" } ]
}
```

Модель взаимодействия — **pull (Вариант B)**: RX даёт только id, текст качаем мы.

## 5. Как продолжить реализацию

План разбит на 6 TDD-задач (полный код приведён в каждом шаге плана):

1. **Конфиг RX** — `RX_ODATA_URL/RX_USER/RX_PASSWORD` в `src/config.py` + `.env.example`.
2. **`src/fio_extractor.py`** — `normalize_fio()` → «Фамилия И.О.».
3. **Доп. поля классификации** — `extract_extra_fields()` + поля `applicant_fio`,
   `summary` в `ClassificationResult`; правка промпта LLM.
4. **`src/rx_client.py`** — `get_document_text(document_id)` (id→версия→тело→текст).
5. **`src/integration_api.py`** — эндпоинт `/integration/classify-document`,
   подключение к `api_server.py` через `app.state.agent`.
6. **Смоук на стенде** + отладка OData-500 + выдача адреса сервиса.

**Task 6 закрыт. Риск снят.** На документе id=**15920** «Чистое обращение» весь путь
отработал end-to-end против живого стенда:
- `rx_client.get_document_text(15920)` → PDF 201 КБ (`Body/$value` → 200, `%PDF-1.5`),
  извлечено 596 символов за ~1.3с.
- `applicant_fio`: «Владленов Игорь Михайлович» → **«Владленов И.М.»**.
- `summary`: корректная суть (жалоба на невывоз ТКО, адрес площадки из текста — верно,
  НЕ галлюцинация; сверено с полным текстом).
- `questions`: 2 кода ЖКХ/ТКО (0005.0005.0056.1164 УК, 0005.0005.0056.1160 ТКО).
- vid=Жалоба, overall_conf=0.55 → needs_verification=True (human-in-the-loop, корректно).

**Про прежние 500 (docs 25–50):** это были ПУСТЫЕ демо-карточки 2023 г. без реального
тела файла — не серверная поломка и не проблема прав. У реальных обращений
(интернет-приёмная, id ~15900+) тело отдаётся штатно. `rx_client._fetch_body` менять
НЕ нужно. Для «пустых» документов сервис корректно вернёт 502 с текстом ошибки.

**Находка (в силе):** несуществующий/некорректный id на стенде отдаёт `400`, а не `404`
→ клиент получает `502` вместо `404`. Решить при желании: маппить 400→404 для «не найдено».

## 7. ⚠️ Открытый риск (Task 6) — ДИАГНОСТИРОВАНО 2026-07-08

**Статус реализации:** код полностью готов (Tasks 1–5), эндпоинт работает
сквозно. Смоук против живого стенда прошёл — но упирается в серверную проблему RX.

**Что подтверждено на живом стенде (172.16.96.98):**
- Метаданные и версии документов читаются нормально (`GET IElectronicDocuments(26)` → 200).
- Скачивание **тела** даёт `500 «Произошла непредвиденная ошибка»` по ВСЕМ путям:
  `Body/$value`, `PublicBody/$value`, `$expand=Body`, вложенный `$expand`.
  `$select=Body` → 200, но без потока. WebAPI `/Web/api` → 404.
- **Проблема системная, не привязана к документу 26:** проверены id 25,26,27,28,30,50 —
  тело не скачалось НИ У ОДНОГО (0/6). Это конфигурация Integration OData на стенде
  (стриминг тела / права), а НЕ баг клиента.
- Клиентские альтернативы из плана исчерпаны — рабочего пути со стороны клиента нет.

**Требуется от администратора RX:** починить стриминг тела документов в Integration
OData (права интеграционного пользователя на Body и/или конфигурация сервиса).
После этого смоук проходит без изменений кода — `rx_client._fetch_body` уже готов.

**Поведение сервиса сейчас (корректное, graceful):** POST `/integration/classify-document`
`{"document_id":26}` → **502** с текстом `Не удалось получить тело документа из RX:
HTTP 500: "Произошла непредвиденная ошибка..."`. Пайплайн, роутер и классификатор
(улучшенный из phase-1: Top-1 26.8%) работают — блокирует только тело.

**Находка (отложено):** несуществующий/некорректный id на этом стенде возвращает
`400`, а не `404`, поэтому ветка `DocumentNotFound→404` не срабатывает — клиент
получает `502`. Пока body-500 маскирует всё, не трогаем (не угадывать семантику 400).
Когда тело починят — решить, маппить ли 400→404 для «не найдено».
